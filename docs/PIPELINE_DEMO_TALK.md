# Nexys4 五级流水课堂讲解稿

## 1. 开场版

大家现在看到的是我这个 RISC-V CPU 在 Nexys4 DDR 板上的硬件演示。

它不是只把程序跑起来，而是把五级流水的执行过程直接映射到板载 LED 和数码管上，所以我们可以在实物上观察指令是怎么经过 `IF、ID、EX、MEM、WB` 这五个阶段的。

## 2. 先讲整体目标

这次我主要想证明四件事：

1. 这颗 CPU 不是单周期，而是真正的五级流水
2. 它不仅能连续跑，还能在板上看到流水中的 stall 和 flush
3. 它已经带有 I-Cache，所以取指也会表现出真实的 cache line 行为
4. 这些现象不是口头描述，而是能够在 FPGA 板上直接观测到

## 3. 板上资源说明

我这里主要用了三类资源：

- LED：显示五级当前是否有效，以及 stall、flush 这类事件
- 数码管：显示某一级当前完整 PC，或者当前指令的完整机器码
- 按键：实现运行、暂停、单步和翻页

这里的控制方式是：

- `btnU` 控制运行和暂停
- `btnL` 每按一次推进 1 个 CPU 周期
- `btnR` 切换 PC 页和机器码页
- `btnD` 切换慢跑速度
- `btnC` 负责复位

## 4. 进入演示模式

我先把 `sw[15]` 置成 `1`，再按复位。

这样系统不会进入原来的串口 shell，而是进入专门为课堂展示准备的短程序。

这段程序会覆盖几类典型现象：

- 顺序执行
- 前递
- `load-use stall`
- `mul/div stall`
- `branch flush`
- I-Cache line 边界处的取指停顿

## 5. 第一段演示词：先看最开始在执行什么

我先把 `sw[2:0]` 设成 `000`，也就是看 F 级。

先看第一页，也就是 PC 页。这里显示的是当前 F 级手上的完整 PC。

再按 `btnR` 切到第二页，也就是机器码页。这里显示的是同一个流水级当前指令的完整 32 位机器码。

比如现在程序开头地址 `0x00000000` 上的第一条指令就是：

```text
00200013
```

所以如果当前 F 级正好在起始位置，你就能在机器码页直接看到 `00200013`。

这里我想强调一点：

- `00200013` 是“地址 `0x00000000` 上存放的机器码”
- 不是“PC 从 `00200013` 开始执行”

PC 始终是地址，机器码始终是该地址里的内容，这两个概念必须分开。

## 6. 第二段演示词：流水在流动

接下来我单步按 `btnL`，或者让它低速慢跑。

这时大家可以看到：

- PC 页里，同一个流水级的地址在变化
- 机器码页里，这个地址对应的指令也在变化

如果我切换 `sw[2:0]` 去看 `D、E、M、W`，还能看到同一时刻不同级别拿着不同的指令。

这就是五级流水最核心的特征：

不是一条指令做完再做下一条，而是多条指令重叠执行。

## 7. 第三段演示词：为什么会停

现在重点看 LED。

如果 `load-use stall` 亮起，就说明：

- 前一条 `lw` 的结果还没准备好
- 后一条指令又立刻要用
- 所以流水线必须停一拍

如果 `mul/div stall` 亮起，就说明：

- `div` 不是单周期完成的
- 它会在 EX 阶段持续若干拍
- 后面的流水必须等它

这说明流水线并不是永远理想前进，它会因为数据相关和运算延迟而真实停顿。

## 8. 第四段演示词：I-Cache 和 cache line

这里我会专门讲一下为什么有时候会看到取指停顿。

当前 I-Cache 不是每次只取 1 条指令，而是按一整条 cache line 取。

这版 I-Cache 的一条 line 是 16 字节，也就是 4 条 32 位指令。

所以地址会自然分组：

- `0x00 ~ 0x0c` 是一条 line
- `0x10 ~ 0x1c` 是下一条 line
- `0x20 ~ 0x2c` 是再下一条 line

当程序从 `0x0c` 走到 `0x10`，或者从 `0x1c` 走到 `0x20` 时，就跨过了 cache line 边界。

如果下一条 line 还没在 I-Cache 里，就会发生 miss，需要整条 refill。这几拍前端取不到有效指令，于是会出现 `ifetch stall`。

所以这里看到的不是错误，而是一个真实存在的缓存层次结构现象。

## 9. 第五段演示词：为什么会看到 0

这个问题老师很容易问，所以最好主动讲。

如果大家看到：

- 正常的 PC 中间突然夹了一个 `00000000`
- 或者机器码页里中间插入了一个 `00000000`

这通常不是程序真的跳回地址 0，而是流水线里插入了一个 bubble。

bubble 可以理解成：

- 流水线里的一格空槽位
- 它不是有效指令
- 但是会像空项一样继续从 `D -> E -> M -> W` 往后流

在当前实现里，如果某拍取指无效，比如 I-Cache miss 还没补完：

- `validD = 0`
- `pcD = 0`
- `instrD = 0`

这个无效项再往后传，你在 `D/E/M/W` 这些级别就可能看到中间穿插的 `0`。

所以正确理解是：

- `0 + valid 失效` 表示 bubble
- 不是“真实执行地址回到 0”

尤其在 `0x10`、`0x20` 这种跨 cache line 的位置，更容易看到这种现象。

## 10. 第六段演示词：为什么复位后不会完全卡住

这里还有一个设计细节。

演示模式复位后不会永远停住，而是会自动先放行少量时钟脉冲。现在这个值设成了 `14`。

它的目的有两个：

- 让 SoC 能从同步复位里正常释放
- 让第一条 I-Cache line 先补齐，板上现象更稳定

所以这不是“程序偷偷先跑很远”，而是为了让板上演示更加可观察。

## 11. 收尾版

所以这套演示最终说明的是：

1. 这颗 CPU 已经具备完整的五级流水结构
2. 流水中的正常流动、停顿和冲刷都能在实板上观测
3. I-Cache 也不是摆设，它会真实影响取指时序
4. 板上看到的 `0` 并不一定是地址 0，很多时候其实是 bubble

如果老师希望，我还可以切回正常模式，进入原来的串口 shell，继续展示 `perf`、`cache` 和其他 SoC 功能。

## 12. 简短问答备稿

### Q1：为什么不用串口直接打印流水状态？

因为串口更适合结果输出，不适合拍级观察。板载数码管和 LED 更适合实时、低延迟地看流水级变化。

### Q2：为什么机器码和 PC 要分成两页？

因为 8 位数码管一次刚好适合显示一个 `32-bit` 值。第一页看地址，第二页看机器码，老师更容易把“PC 是地址”和“指令是内容”分开理解。

### Q3：为什么 `0x10`、`0x20` 附近更容易看到异常？

不是异常，而是 cache line 边界。跨过 16B 边界时更容易 I-Cache miss，miss 时会产生取指停顿和 bubble。

### Q4：为什么会看到 `00000000`？

有两种常见情况：

- 当前地址后面本来就没有更多有效指令
- 当前级当前是 bubble，显示成了 0
