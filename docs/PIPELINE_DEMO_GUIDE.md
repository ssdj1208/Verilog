# Nexys4 五级流水演示使用指南

## 1. 目标

这套演示模式用于在 Nexys4 DDR 板上直观展示当前 RISC-V CPU 的五级流水执行过程。它和原有串口 shell 模式并存：

- `sw[15] = 0`：正常模式，继续进入原有 boot 自检和 UART shell
- `sw[15] = 1`：演示模式，进入专用流水线展示程序

演示模式不会依赖 UART 输入，也不会进入 DDR benchmark，重点是稳定观察流水线在板上的流动、停顿、冲刷，以及 I-Cache 带来的取指现象。

## 3. 板上资源分配

### 3.1 按键

- `btnC`：复位
- `btnU`：运行/暂停切换
- `btnL`：单步推进 1 个 CPU 周期
- `btnR`：切换数码管显示页
- `btnD`：切换慢跑速度

### 3.2 开关

- `sw[15]`：模式选择
  - `0` 为正常模式
  - `1` 为流水演示模式
- `sw[2:0]`：选择当前观察的流水级
  - `000`：IF/F
  - `001`：ID/D
  - `010`：EX/E
  - `011`：MEM/M
  - `100`：WB/W

### 3.3 LED

- `led[4:0]`：`F / D / E / M / W` 五级当前是否有效
- `led[5]`：`load-use stall`
- `led[6]`：`mul/div stall`
- `led[7]`：`ifetch stall`
- `led[8]`：`dcache stall`
- `led[9]`：`branch flush`
- `led[10]`：`trap flush`
- `led[11]`：暂停状态指示
- `led[12]`：运行状态指示
- `led[13]`：当前是否在详情页
- `led[14]`：当前慢跑速度档位
- `led[15]`：当前是否处于演示模式

### 3.4 数码管

数码管有两页显示，由 `btnR` 切换。

#### 页面 A：PC 页

- 8 位数码管显示 `sw[2:0]` 选中的那个流水级当前完整 `32-bit PC`
- 页 A 不再显示五级缩略编号，而是直接显示一个级别的完整地址
- 最低位小数点用于标记该级当前是否 `valid`
  - 小数点亮：该级当前有有效指令
  - 小数点灭：该级当前是空泡或无效级

#### 页面 B：机器码页

- 8 位数码管显示同一个流水级当前指令的完整 `32-bit` 机器码
- 例如当前级里是 `li x1,3`，就会显示 `00300093`
- 如果该级当前是 bubble，通常会看到 `00000000`

## 4. 当前演示程序

当前 `boot.mem` 开头指令如下：

```text
00000000: 00200013  li x0,2
00000004: 00300093  li x1,3
00000008: 00400113  li x2,4
0000000c: 00400193  li x3,4
00000010: 00400293  li x5,4
00000014: 00400393  li x7,4
00000018: 00100433  add x8,x0,x1
0000001c: 003104b3  add x9,x2,x3
00000020: 00418533  add x10,x3,x4
```

也就是说：

- 复位后真正的起始取指地址是 `PC = 0x00000000`
- 地址 `0x00000000` 里存放的第一条机器码是 `00200013`
- `00200013` 是“地址 0 上的指令内容”，不是“PC 从 00200013 开始执行”

## 5. 演示模式的启动节拍

当前 `demo_clock_ctrl` 里使用了 `STARTUP_PULSES = 14`。

它的作用不是让程序“自由跑很久”，而是让演示模式复位后自动前进少量拍数，完成两件事：

- 让 SoC 从同步复位中稳定释放
- 让第一条 I-Cache line 预取完成，避免一上来就完全停在 refill 之前

为什么不是 `0`：

- 如果完全不自动送拍，`soc_clk` 不动，`soc_rst` 也无法靠同步移位释放
- 板上会看起来像“复位后死住了”

为什么不是更大的值：

- 如果自动前进过多拍，开头几条指令已经流走，课堂上不容易直接看到第一条机器码

`14` 是在“能正常起机”和“不会把开头冲走太多”之间的折中值。

## 6. I-Cache 说明

### 6.1 什么是 cache line

当前 I-Cache 是只读取指缓存，参数是：

- 64 lines
- 每条 line 有 4 个 word
- 每个 word 4 字节

所以一条 cache line 的大小是：

`4 x 4B = 16B`

也就是按地址看，每 16 字节为一组：

- `0x00 ~ 0x0c` 是第 1 条 line
- `0x10 ~ 0x1c` 是第 2 条 line
- `0x20 ~ 0x2c` 是第 3 条 line

### 6.2 为什么 `0x10`、`0x20` 附近容易出问题

因为这些地址正好跨过 16B 边界。

例如：

- 从 `0x0c` 到 `0x10`：从第 1 条 line 跳到第 2 条 line
- 从 `0x1c` 到 `0x20`：从第 2 条 line 跳到第 3 条 line

如果新 line 还没有在 I-Cache 里，就会发生 I-Cache miss，需要整条 refill。

### 6.3 miss 时发生什么

miss 时，I-Cache 不会只取 1 条指令，而是把整条 16B line 都补进来。这个过程会经历多拍：

- `ISSUE`
- `CAPTURE`
- `COMMIT`

在 refill 期间：

- `i_readyF = 0`
- IF 当前拍拿不到有效指令
- 前端会暂时停住

这就是 `ifetch stall` LED 亮起的来源之一。

## 7. 什么是 bubble

bubble 就是“流水线里的一格空槽位”。

它不是一条真实指令，但会像一条空指令一样在 `D -> E -> M -> W` 中向后流动。

在当前实现里：

- 如果当前拍取指无效，`instrD` 会写成 `0`
- 同时 `pcD` 也会写成 `0`
- `validD = 0`

随后这个无效项会继续传播到 `E/M/W`。

所以当你看 `D/E/M/W` 某一级时，数码管中间偶尔穿插一个 `00000000`，通常不是 CPU 真的跳回了地址 0，而是：

- 当前级无效
- 当前级里是 bubble
- 面板把这个 bubble 用 `0` 显示出来了

判断方法：

- 看页 A 时，如果最低位小数点灭了，说明该级当前 `valid = 0`
- 这时看到 `00000000`，优先理解为 bubble，而不是“真实 PC 回 0”

## 8. 推荐演示流程

### 8.1 进入演示模式

1. 将 `sw[15]` 拨到 `1`
2. 按 `btnC` 复位
3. 观察 `led[15]` 亮起，表示进入演示模式

### 8.2 先看起始 PC 和起始机器码

1. `sw[2:0] = 000`，选择 F 级
2. 保持在页面 A，观察起始 PC 是否靠近 `00000000`
3. 按 `btnR` 切到页面 B
4. 观察 F 级机器码是否出现 `00200013`

### 8.3 再看单步推进

1. 按 `btnL` 单步
2. 页面 A 看所选级 PC 如何变化
3. 页面 B 看对应机器码如何从 `F -> D -> E -> M -> W` 流动

### 8.4 展示 I-Cache line 边界

建议固定看 F 或 D 级，然后讲：

- `0x00 ~ 0x0c` 在同一条 line
- 到 `0x10` 时跨 line，容易看到 `ifetch stall`
- 中间插入的 `00000000` 很可能是 bubble，不是乱跳回 0

### 8.5 展示 stall 和 flush

1. 继续单步或慢跑
2. 当 `led[5]` 亮时，说明出现 `load-use stall`
3. 当 `led[6]` 亮时，说明出现 `mul/div stall`
4. 当 `led[9]` 亮时，说明发生 `branch flush`

## 9. 常见现象解释

### 9.1 为什么机器码页里会出现 `00000000`

常见原因有两个：

- 当前地址后面本来就没有写更多有效指令
- 当前级当前是 bubble，机器码被显示成 `0`

### 9.2 为什么 PC 会在正常地址中间短暂显示成 0

如果看的不是 F，而是 `D/E/M/W`，这通常是 bubble：

- 取指 miss
- 当前拍没有有效新指令
- `pcD` 写成 `0`
- 这个无效项继续流到 `E/M/W`

尤其在 `0x10`、`0x20` 这些跨 cache line 的地方更容易看到。

### 9.3 为什么复位后不是永远停在第一拍

因为演示模式为了能正常从复位释放并预取第一条 cache line，默认会自动放行 `14` 拍启动脉冲。

## 10. 结束后如何回到原系统

1. 将 `sw[15]` 拨回 `0`
2. 按 `btnC` 复位
3. 板子会回到原来的正常模式
4. 串口会重新进入 boot 自检和 `rv32>` shell
